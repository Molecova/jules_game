2026-10-07 · `Molecova/jules_game` · `ccr-5e12923f-aw0cjb`

평가 범위를 **유닛 27종·스킬 64종·무기 38종, 모두 ★1·★2·★3**으로 확장했다. 유닛·고유기 12종, 스킬 17종, 무기 11종의 데이터와 여러 공통 성급 계산을 수정했다. 이번 카드 패치의 적 능력치·편성·난이도 자원은 직전 커밋 `2d0300d`와 같다.

같은 조건의 보통 원정 36회에서 직전·수정 버전 모두 완수 9회였고, 최종 보스 직접 처치는 5회→8회였다. 자동 플레이가 모든 사람의 판단을 재현하지는 않으며, 이 작은 표본만으로 승률 개선을 확정할 수 없다. 지옥의 완수 가능성은 이번에도 검증하지 못했다.

보스 수치는 보통 난이도, 해당 막 마지막 노드의 본체 기준이며 공격은 반올림했다. 녹스는 최초 패치 전 대비 HP **57.9%**, 공격 **82.0%** 감소, 모르간은 HP **51.8%**, 공격 **74.6%** 감소했다. 10종 보스 전체와 적 성장 공식은 [이전 보고서](balance-2026-10-07.md)에 있다.

고난도 수입은 원본 커밋의 실제 코드를 다시 확인해 정정했다. 예전 README의 ‘수입 −1’ 설명과 달리 `9f798db`의 실제 기본 수입은 모든 난이도에서 5였다. 이전 보고서의 해당 설명도 고쳤다.

이전 평가에서는 같은 시드·같은 정책의 보통 원정이 **0/36→10/36 완수**, 최종 보스 직접 처치 **0/36→8/36**였다. 아래 이번 평가의 **9/36→9/36**은 별도의 시드와 보완된 정책으로 얻은 직전·이번 카드 버전 비교다. 서로 다른 평가 표본을 연결해서 0→10→9라는 추세로 해석하면 안 된다.

## 2. 카드와 성급 변경

등급은 구매 가격인 1~5등급, 성급은 합성 결과인 ★1~★3이다. 합성은 같은 카드 1 / 3 / 9장이 필요하다. 유닛 HP·공격 배수 **1 / 2 / 4**, 유닛 고유기 위력 **1 / 1.7 / 2.8**, 칩 위력 **1 / 1.7 / 2.6**, 무기 능력치 **1 / 1.6 / 2.5**는 유지한다. 강화 시 출전·장착 한 칸에 더 많은 전력을 담는 구조다.

### 공통 성급 계산·설명 수정

- 즉시 화상·중독·출혈에 스킬 위력을 반영한다. 예고형 화상에도 칩 성급을 적용하고, 독 장판·칼날 출혈도 같은 규칙으로 맞춘다. 유닛 성급을 두 번 곱하지 않는다.
- 신의 가호의 부가 회복에도 유닛·칩 성급과 스킬 위력을 적용한다. 보호막은 기존 HP 50% 상한을 유지한다.
- 무기 액티브의 위력은 칩의 ×1/1.7/2.6 대신 **무기의 ×1/1.6/2.5**를 쓴다. ★3 액티브의 발 수 증가와 성급별 쿨다운은 유지한다.
- 카드 정보에 현재 칩 성급의 지속 피해, 무기 성급의 치명 피해·회피, 소환물 강화, 음수 사거리를 올바르게 표시한다.

구체적으로 같은 **2성 마법사 + 3성 메테오 + 3성 화염 지팡이**, 다른 시너지·유물 없이 화상의 상태 수치는 **초당 68→309.4**다. 직전 예고형 화상에서 빠졌던 칩 배수와 주문 강화를 함께 적용한 결과다. 적 방어·추가 피해 보정 후 실제 HP 감소량은 별도다.

**3성 마법사 + 3성 신의 가호**, 무기·시너지 없이 부가 회복의 상한 전 수치는 **135→728**이다. 무기 단궁 액티브의 한 발 위력은 1성 유닛 기준 ★1/2/3 **90/153/234→90/144/225**로 수정됐다. 성급 계산을 맞추면서 증가한 효과와 감소한 효과를 모두 기록했다.

## 3. 평가 방법과 실제 원정 결과

### 카드 전수 진단

`scripts/card-audit4.cjs`는 실제 전투·편성·시너지 코드를 사용해 다음을 측정한다.

- 유닛: 27종 × 3성급 = **81개 수치 행**.
- 스킬: 64종 × 유닛 3성급 × 칩 3성급 = **576개 행**.
- 무기: 38종 × 장착 유닛 3성급 × 무기 3성급 = **342개 행**.
- 합계 **999개 성급 조합**. 각 조합에 일반전·보스전과 3개 전투 시드를 적용하여 버전당 **5,994전**, 전후 총 **11,988전**을 기록했다.

고정된 4인 부대의 한 칸을 교체하거나 장비를 장착한 진단이다. 유닛 성급 1/2/3에는 각각 1/2/4막의 전투를 사용한다. 같은 비교 안에서는 적·배치·동료·시드가 같고, 장비 기여도는 장비 없는 같은 부대와 비교한다. 피해뿐 아니라 회복·보호막·생존·처치·실제 시전 횟수를 기록한다.

이는 **카드 효과를 분리하는 실험**이다. 이 부대를 실제 상점에서 샀다는 뜻도, 사람의 완수율도 아니다. 생존 시간이 늘면 총 피해도 늘고, 빨리 적을 처치하면 총 피해가 줄 수 있으므로 피해 하나로 순위를 정하지 않는다. 직선 공격은 정렬된 배치에서 측정하며 실제 원정의 오배치 가능성은 다음 검사에서 반영한다.

대표적으로 2성 장착 유닛 기준, 3성 사냥매 호루라기는 같은 6개 진단 전투에서 처치 승리 **0→1**, 팀 평균 피해 **10,286→12,006**이었다. 3성 성서는 평균 회복·보호막 **3,594→5,441**, 3성 흡혈귀의 검은 처치 승리 **1→4**였다. 불굴의 함성의 회복·보호막은 **4,346→3,800**으로 감소했다. 여기의 승리를 실제 원정 완수와 섞지 않는다.

### 실제 구매·합성 원정

[기존 전체 원정 플레이](balance-2026-10-07.md)의 세 성향을 사용한다. 공개된 현재 상점·보스·경로만 보고 실제 가격을 지불하고 합성·장착·판매·레벨업·이벤트·전투·보상을 처리한다. 미래 RNG 조회, 전투 결과 예측, 패배 전으로 되돌리기, 임의 카드·골드 지급은 하지 않는다.

후위 마법사가 자기 주변 1칸 폭발만 과대평가하던 판단을 보완했다. **이 동일한 정책을 직전·이번 버전에 모두 적용**했다. 버전마다 잘 맞는 정책을 따로 고르지 않았다. 기존 버전의 카드 패치 파일도 함께 로드하도록 비교 도구를 수정했다.

최종 보통 시드: `66000001 + i × 7919`, 성향별 `i=0..11`.

| 성향 | 직전 완수 → 이번 완수 | 직전 최종 보스 처치 → 이번 처치 |
|---|---:|---:|
| 단순 강화형 | 3/12 → 4/12 | 3/12 → 3/12 |
| 혼합 성장형 | 3/12 → 3/12 | 2/12 → 3/12 |
| 조합 추구형 | 3/12 → 2/12 | 0/12 → 2/12 |
| 합계 | **9/36 → 9/36** | **5/36 → 8/36** |

완수에는 불사조로 마지막 패배를 넘긴 경우가 포함된다. 직접 처치는 실제 마지막 보스전 승리이면서 제한시간 판정도 아닌 경우만 센다. 성공·실패 모두 원본 기록에 보관한다. 세 성향은 같은 12개 시드를 공유하므로 36개 독립 원정 시드로 보지 않는다.

수정 버전의 보통 원정에서 실제 출전한 카드는 유닛 **26/27종**, 스킬 **64/64종**, 무기 **37/38종**이었다. 관측된 카드·성급 조합은 각각 61·87·60개였다. 실제 원정에서 나오지 않은 카드나 성급도 고정 카드 진단과 수치·동작 검사에 포함했다. 보통과 고난도 전후 최종 144회에서 골드·소유·카드 풀·출전 제약 검사 **61,238회**를 통과했다.

고난도 시드: `68000001 + i × 7919`, 성향별 `i=0..5`.

| 난이도 | 직전 완수 → 이번 완수 | 직전 직접 처치 → 이번 처치 |
|---|---:|---:|
| 어려움 | 0/18 → 1/18 | 0/18 → 1/18 |
| 지옥 | 0/18 → 0/18 | 0/18 → 0/18 |

지옥은 여전히 완수가 없어 균형이 검증됐다고 판단하지 않는다. 진단에서 좋아진 카드를 자동 플레이가 반드시 구매·합성한다는 보장도 없다. 특히 높은 등급 ★3의 구매·합성 비용과 등장 확률 때문에 고정 진단의 강함을 그대로 원정에 적용할 수 없다. 실제 사람의 구매·배치 기록을 함께 비교하는 후속 검증이 필요하다.

## 4. 검증과 사용 자료

**회귀 테스트 350개 통과**. 모든 유닛과 호환 무기의 1·2·3성 조합, 유닛·칩·무기 성급을 함께 바꾼 지속 피해·회복의 배수, 액티브 발 수·위력, 소환·집중 강화, 유틸리티 지속·HP 비용, 편집 시트와 실제 데이터의 일치를 검사했다. 기존 보스 제어·신규 무기·이펙트 결정성·카드 풀·저장 검사는 적용된 `balance4.js`를 읽도록 고쳤다.
