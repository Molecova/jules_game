# A안: 게임판과 배경부터 시작하는 입체 보드

이 문서는 최초 3D 연결 단계의 기록이다. 이후 PBR 재질과 5막 환경을 개선한 결과는 [게임판·배경 개선 기록](tabletop-board-background-implementation-2026-10-08.md)에 정리했다. 아래의 절차적 재질 관련 한계는 최초 구현 당시의 상태다.

원본 `Molecova/jules_game`, 브랜치 `ccr-5e12923f-aw0cjb`, 기준 `7d5c961ebbf1479636f59506dbd38acd765a9100`을 최신 pull한 뒤 별도 체크아웃 `/workspace/jules_game-tabletop3d`로 분리했다. 원본의 미추적 보고서나 작업 파일을 옮기지 않았다. 동일 소유자의 프로젝트는 GitHub에서 직접 포크할 수 없어 이력 보존 독립 복제로 준비한다. 목표 저장소는 `Molecova/jules_game-tabletop3d`, 로컬 개발 브랜치는 `main`이다.

GitHub GraphQL `createRepository`와 REST `POST /user/repos`가 모두 연결 앱 권한 부족으로 거절됐다(REST 403 `Resource not accessible by integration`). 따라서 원격 독립 저장소는 아직 생성되지 않았다. 실제 플레이 미리보기는 원본 저장소의 새 `tabletop-a-3d` 브랜치에 게시하며, 원본의 작업 브랜치는 그대로 유지한다. 사용자가 빈 목표 저장소를 만들고 앱에 접근을 허용하면 로컬 복제본의 전체 이력을 새 원격에 푸시할 수 있다. 생성 실패를 GitHub 포크 완료라고 표시하지 않는다.

## 이번 구현

- `v4/tabletop4.js`: Three.js 정사영 카메라, 목재 받침·프레임, 두께 있는 30개 타일, 프레임의 나사·좌표 인쇄, 주변 돌·잔디·작은 폐허, 실제 조명과 그림자.
- 1~5막: 숲·폐허·사암·설원·밤의 유적 색상과 재질. 지형 소품은 보드 테두리에만 놓아 전투 칸에 장애물을 추가하지 않는다.
- 딱지: 기존 초상화를 실제 두께 있는 원판 위에 인쇄. 장비 모형·여러 칩 장식은 전장에서 생략한다. 높은 성급은 작은 금색 핀으로 표시한다. 기존 상세 카드에서 스킬·무기 정보와 장착을 확인할 수 있다.
- 기존 Canvas 2D 스킬·체력·투사체 연출을 투명 텍스처로 보드 위에 연결한다. 모든 효과를 3D 입자로 다시 만든 단계는 아니다.
- 터치와 드래그: 화면 좌표를 보드 평면으로 역투영해 기존 배치 함수를 호출한다. 기존 창고·판매·교환 입력을 유지한다.
- `v4/tabletop4.css`: 게임 UI와 보드를 구분하는 남색 HUD, 차분한 매트, 금색 전투 버튼.
- 게임에 필요한 Three.js를 공식 배포물 그대로 저장소에 포함해 CDN 의존성을 제거한다.

전투 엔진·유닛·스킬·무기·밸런스·적 편성·저장 모듈은 기준 커밋과 동일하다. 컨트롤러의 변경도 렌더러 연결, 화면 좌표 변환, 그림 표시 범위뿐이다. 시각 효과용 난수는 전용 생성기를 사용한다.

## 확인

기존 Node 회귀 검사 **350개 통과**. 기존 브라우저 시작·상점·실제 전투·저장·재개 및 v3 시작 검사 통과.

새 브라우저 검사는 390×844·360×640·768×1024에서 다음을 확인한다.

- 30개 칸 각각의 화면 투영→보드 역투영 일치, 가로 넘침 없음, 전투 버튼이 화면 안에 표시됨.
- 실제 상점 가격을 지불한 3개 클래스 유닛 구매, 보드 이동과 보드↔창고 드래그.
- 렌더링 중 원정 RNG 불변.
- 동일 편성의 실제 전투와 기존 시뮬레이션의 승패·전투 시간 일치, 결과 저장·재개 시 전투 횟수 중복 없음.
- 5막 배경 전환, 명시적인 2D 모드, WebGL 컨텍스트 손실 시 2D 복귀.
- 브라우저 JavaScript 예외와 콘솔 오류 **0**.

## 구현의 현재 한계

시안의 정교한 인물 미니어처 모델을 제작한 단계는 아니다. 이번 목표에 맞춰 딱지를 간결하게 유지하고 실제 3D 게임판·배경을 먼저 만들었다. 재질은 코드로 만든 나뭇결·종이 질감을 사용하며 사진 스캔 기반 PBR 재질과 전문 환경 모델은 포함하지 않는다.

화면을 30fps 이하로 그리며 픽셀 비율은 1.5 이하, 그림자 맵은 1024로 제한한다. 정지한 말의 그림자는 재사용한다. 클라우드 Chromium의 소프트웨어 GPU로 기능과 화면 크기를 검사했으며 실제 휴대폰의 발열·배터리·프레임 성능을 측정했다는 뜻은 아니다.

WebGL을 사용할 수 없거나 컨텍스트가 손실되면 기존 2D 보드로 돌아간다. `?view=2d`로 직접 선택할 수도 있다. 새 저장 형식을 만들지 않아 기존 게임 상태와 호환된다.

## 이어서 할 작업

먼저 실제 플레이에서 판의 크기·색·카메라를 확정한다. 그 뒤 전문 나무·종이 재질과 테두리 지형을 개선하고, 원하는 경우 6종 미니어처 GLB를 추가한다. 미니어처 개발은 현재의 간결한 딱지와 교체할 수 있게 렌더러에서 분리해 진행한다.

```bash
python3 -m http.server 8001 --bind 127.0.0.1
node --test tests/*.test.cjs
node tests/browser-tabletop4.cjs
```
